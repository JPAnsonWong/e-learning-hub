# 每日打卡：啟用步驟與使用說明

孩子在網站「今日打卡」頁打卡，任務來自 Notion 的「每日任務」資料庫，打卡結果每 15 分鐘同步回 Notion，爸爸只需要在 Notion 糾正不對的地方。

```
Notion（每日任務、重要日子）⇄ GitHub Actions（每 15 分鐘）⇄ Firebase ⇄ 網站「今日打卡」
```

## 一次性啟用（照順序做）

### 1. 更新 Firestore 安全規則
網站只能「切換打卡狀態」，不能新增、刪除或改分數。
1. 打開 Firebase 主控台 → Firestore Database → **規則**。
2. 把倉庫裡 [firestore.rules](../firestore.rules) 的全部內容貼上，按**發布**。

### 2. 設定 GitHub Secret
同步程式需要知道「每日任務」等資料庫在哪個 Notion 頁面底下。
```
gh secret set NOTION_DAILY_PARENT_ID --repo JPAnsonWong/e-learning-hub
```
貼上上層頁面的網址或 32 位 ID（也就是 `.env.local` 裡的 `NOTION_DAILY_PARENT_ID`）。`NOTION_TOKEN` 和 `FIREBASE_SERVICE_ACCOUNT` 之前已設定。

### 3. 先「演練」一次
GitHub → Actions → **Sync daily check-in** → **Run workflow**，勾選 **dry_run**。
日誌只會印數量（例如「生成：今日 25 項、本週 9 項」），不寫入任何東西。數量合理再做下一步。

### 4. 正式執行一次
再按一次 **Run workflow**（不勾選 dry_run）。它會：
- 在 Notion「每日任務」建立今天的任務列（只為女兒、兒子；爸爸、媽媽的任務不生成）；
- 同步到網站；
- 同步「重要日子」的倒數日；
- 建立積分總表（起始總分取自 People 的 Total Points，之後凍結不再改動）。

之後每 15 分鐘自動執行。

### 5. 停掉舊的排程
舊的 TaskReminder（Windows 工作排程器）要停用，否則會重複計分。

## 每天怎麼運作
- **每天第一次同步**（香港時間 00:00 後）依 `Routine Items` 生成當天任務；每週一同時生成「每周任務」（整週內打卡一次計一次分）。
- **你在 Notion 刪掉的任務不會被重新生成**；你手動新增的列（填日期、孩子、分類、積分）會自動同步到網站。
- **孩子打卡** → 網站即時生效 → 約 15 分鐘內 Notion 的「打卡」被勾上，並記錄「打卡時間」。
- **爸爸糾正**（在 Notion「每日任務」）：
  - 改「積分」（改 0、改分）→ 網站顯示「爸爸已更正」；「備註」會顯示給孩子看。
  - 取消「打卡」勾選 → 網站顯示「爸爸已更正：這項未通過」，孩子不能再改。
  - 「積分」留空 = 待評分；你填了分數才計入。
- **積分確認**：某天的打卡積分，在「次日中午 12:00（香港時間）」後自動計入總分；每周任務在下週一中午確認。確認前顯示為「待確認」。**請在次日中午前完成糾正**，確認後再改不會影響總分。
- **總分** = 舊 Notion 總分（起始值）＋ 學習積分（作答）＋ 已確認的打卡積分。
- 短時間內連續打卡 5 項以上，Notion 會自動勾上「⚠ 連續快速打卡」，方便你檢查。

## 在 Notion 維護
- **Routine Items**：任務範本。`Person` 選女兒／兒子（可多選）；`Frequency` 選 Daily 或 Weekly；`Points` 是預設分數；`適用星期` 空白＝每天；`選填` 勾選＝不影響「全部完成」。改了範本，**明天才會生效**（今天已生成的不變）。
- **重要日子**（倒數日）：填「事項、日期、對象（女兒／兒子／全家）、說明、類型」；勾「隱藏」就暫時不顯示。倒數天數網站自己算，不受同步延遲影響。
- 建議在 Notion 為「每日任務」加幾個檢視：今日（日期＝今天）、待評分（打卡已勾且積分為空）、異常（⚠ 連續快速打卡已勾）。

## 常見問題
- **打卡頁顯示「今天還沒有任務」**：同步還沒跑過。到 Actions 手動執行一次。
- **打卡時提示「還沒有寫入權限」**：步驟 1 的安全規則還沒發布。
- **Notion 上看不到孩子剛打的卡**：最長等 15 到 30 分鐘；急用就手動執行同步。
- 同步日誌只印數量，不印任務名稱或孩子名字（倉庫公開，日誌也是公開的）。
