# 規則與 Skill 版本更新說明

適用文件：
- `ai-html-rules.md`：給負責**創建 HTML** 的 AI
- `SKILL.md`：給負責**上傳教材（開 PR）** 的 AI

**目前版本：v4**

## 怎麼使用這份文件
1. 先確認你（AI）上次讀的是哪一個版本。**只需要從「你尚未讀過的最舊版本」往上讀到最新（v4）**，不必重讀全文。
2. 每個版本分成「對新頁面」和「對既有頁面」：新頁面直接照做；已經做好的頁面，按「對既有頁面」補上改動。
3. 讀完後，在你的工作記錄裡把已讀版本更新為 v4。
4. 兩份規則文件開頭都有「規則版本」；版本號與這裡不一致時，以這裡最上方的版本為準，並請使用者提供最新文件。

給使用者：新版本發布時，只把最新幾節複製給 AI 即可。若 AI 上次讀的是 v2，給它 v3 和 v4 兩節；若它從沒讀過規則，才給 `ai-html-rules.md` 全文。

## v4：斷點續做（2026-11-15）

### 為什麼改
孩子做 45 題做到第 30 題想暫停，下次回來要能回到第 30 題，而不是從頭開始。網站現在會保存「做到哪裡」，重開時問「繼續／重新開始」。續做時**接續同一個場次**，已答的 30 題和累計用時都保留，所以回來再做 15 題仍算完整的 45 題。

### 對新頁面（`ai-html-rules.md`）
- 新增小節「斷點續做（有 10 題以上的教材必須加）」，要求頁面做兩件事：
  1. 每次畫面更新後，用 `elhReport({type:"state", data:{ i, p, r, ... }})` 回報進度快照。`data.i` 是**目前題號索引（從 0 起）**，網站用它顯示「上次做到第 N 題」；快照不超過約 8000 字元，只放「做到哪裡」，不放題目內容；封面或尚未開始時不要回報。
  2. 監聽 `message`：收到 `{elh:1, type:"restore", data}` 時，先檢查資料合法（`i` 在範圍內），再把狀態設回去並重新繪製。
- 還原時**不要**再回報 `answer`（已答的題目網站已經記錄）。
- 全部答完後網站自動清除快照；教材改版（`meta.json` 的 `version` 加 1）後舊快照自動作廢。
- 「交付前自我檢查」新增一項：10 題以上的教材已加入 `elhState()` 和 `restore` 監聽，並用 `?elhdebug` 確認換題時印出 `type:"state"`。

### 對既有頁面
10 題以上而且已有作答回報（v1）的頁面，補上下面這段。**放在最後一個 `</script>` 之前**；它假設頁面有 `render()` 函式，以及 `i`（目前題號，`-1` 表示封面）、`picked`（目前題所選選項）、`revealed`（答案是否已揭曉）三個變數，若變數名稱不同請對應修改，若頁面有 `seen` 集合（已看過的題）會一併保存。

```js
// ---- E_learning Hub 斷點續做：回報進度快照，並在網站要求時還原 ----
function elhState(){
  try{ if(i>=0) elhReport({type:"state", data:{i:i, p:picked, r:revealed, seen:(typeof seen!=="undefined"?Array.from(seen):[])}}); }catch(e){}
}
(function(){ var _r=render; render=function(){ _r.apply(this,arguments); elhState(); }; })();
window.addEventListener("message", function(e){
  var m=e.data; if(!m||m.elh!==1||m.type!=="restore"||e.source!==window.parent)return;
  var d=m.data||{}; var n=題目總數;   // 例如 QUESTIONS.length
  if(typeof d.i!=="number"||d.i<0||d.i>=n)return;
  i=d.i; picked=(typeof d.p==="number"?d.p:null); revealed=!!d.r;
  if(typeof seen!=="undefined"&&d.seen)d.seen.forEach(function(k){seen.add(k);});
  render();
});
```
補上後把該教材 `meta.json` 的 `version` 加 1。

### 對上傳說明（`SKILL.md`）
- 開頭新增「規則版本」行。
- 第 5 步 `meta.json` 說明補充：
  - **改了題目、題數或題目順序時 `version` 一定要加 1**（否則舊的續做快照會把孩子帶到錯誤的位置）。
  - `minutes` 要填得合理（見 v3）。
  - 有題目的教材 `q` 必須穩定（見 v3）。
- 自我檢查清單新增：HTML 已對照 `ai-html-rules.md` 的交付前檢查；`minutes` 合理；修改既有教材時 `version` 已加 1 且題號沒有重編。

## v3：積分改由場次算出（2026-11-15）

### 為什麼改
原本「點完成」就加分，可以連點刷分，而且有記錄卻不用記錄。現在積分完全由系統記錄到的作答和停留時間算出，頁面**不需要也不應該**自己做任何計分。

### 新的積分規則（頁面只需知道，不需實作）
- 某題**第一次答對** +1；**之前答錯、之後改對** +2；已答對過的題再答對 0；答錯、跳過、未做 0（不扣分）。
- 一個場次答完至少 **80%** 題目才算有效場次，有完成獎勵：同一教材第 1 次 +2、第 2 和 3 次 +1，之後 0；同一教材同一天只有一次。
- 同一場次內先答錯再改對，只看**第一次**作答。
- 沒有題目的教材：工具列的「我學完了」按鈕，停留時間要達到預計學習分鐘數的一半（至少 60 秒）才算完成並得分。

### 對新頁面（`ai-html-rules.md`）
- 新增小節「積分怎麼算（所以回報必須準確）」。要點：
  1. `init` 的 `total` 必須等於需要作答的題目總數。
  2. **`q`（題號）必須穩定**：同一道題日後改版時要保持同一個 `q`，新增題目用新的 `q`，不要重新編號。
  3. 只在揭曉答案那一刻回報；不要擋住重答。
  4. 有題目的頁面**不要**放自己的「完成」按鈕。
- 「沒有作答的教材」一節改寫：說明「我學完了」的停留門檻，所以 `meta.json` 的 `minutes` 要合理。

### 對既有頁面
- 移除頁面內自己的「完成」按鈕或任何自己的計分、分數顯示。
- 若曾經重新編號過題目（`q` 與舊版不同），改回與舊版一致；做不到就把 `version` 加 1 並告知使用者，這份教材的題目會被當成新題重新計分。

### 其他（使用者介面，與 AI 無關）
移除「取消完成」按鈕與「匯出／匯入進度」功能；有題目的教材不再顯示完成按鈕，改顯示「已答 n/總題數」。

## v2：65 寸觸控投屏機版面規則（2026-11-15）

### 為什麼改
最主要的使用場景是 65 寸觸控投屏機（寬約 145 cm、高約 83 cm，16:9 橫向，4K）。螢幕寬而矮，且需要輸入文字時螢幕鍵盤會蓋住約三分之一到一半的畫面。

### 對新頁面（`ai-html-rules.md`）
新增第二節，重點：
- **左右分欄**（約 55:45 或 60:40），題目說明、指示語、題號、進度都放進欄位內。
- 不做橫跨整寬的頂部標題列（若一定要有，高度不超過視窗 6%）；不用固定在底部的操作列；一屏一題，整頁不捲動。
- 字體：題幹 3.6 至 5 vmin，選項 3 至 4 vmin，說明不小於 2.4 vmin。
- **需要輸入的題目**：輸入框、題目重點、提交按鈕都放在螢幕上半部（距頂部 55% 以內）；數字題首選頁面內建大按鈕數字鍵盤（每個不小於 8 vmin，輸入框設 `readonly` 加 `inputmode="none"`）；必須用系統鍵盤時，聚焦時捲到上方並在最底留 50vh 空白。
- 觸控：可點擊區域不小於 `max(3rem,7vmin)`；拖放題必須同時支援「先點選、再點目標」；不依賴雙擊、長按、懸停。
- 「交付前自我檢查」新增版面與鍵盤相關項目。

### 對既有頁面
- 依第二節檢查版面：有橫跨整寬的頂部標題列、固定底部操作列、輸入框在下半部、只能拖放的頁面，需要改。
- 改版後把 `meta.json` 的 `version` 加 1。

## v1：基礎規則與作答回報（2026-11-15）

基準版本，內容見 `ai-html-rules.md` 第一節（基本要求）、第三節（作答回報）和「交付前自我檢查」，以及 `SKILL.md` 全文。要點：
- 單一 HTML 檔、無外部資源、不得出現孩子姓名和學校（用「女兒」「兒子」）。
- 有題目的頁面必須加 `elhReport`／`elhText`，頁面載入時回報 `init`（總題數），每題揭曉答案時回報 `answer`（`q`、`choice`、`correct`、`text`、`picked`、`answer`），用 `?elhdebug` 在 Console 自測。
- 上傳流程：開分支、`meta.json`、本機驗證、開 PR，不得自行合併。

## 維護這份文件的規則（給 AI 和使用者）
每次更新 `ai-html-rules.md` 或 `SKILL.md`：
1. 在本檔「版本一覽」表最上方新增一列，並在表格後新增一節（最新的放最上面）。
2. 新的一節要包含：**為什麼改**、**對新頁面**（改了哪些規則）、**對既有頁面**（要怎麼補，盡量附可直接貼上的程式碼）、**對上傳說明**（如有）。
3. 把兩份規則文件開頭的「規則版本」和本檔的「目前版本」同步改成新版本號。
4. 不要改動舊版本的小節內容，只新增。
