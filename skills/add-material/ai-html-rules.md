# 製作 E_learning Hub 教材 HTML 的規則（給負責「創建 HTML」的 AI）

你要製作一份**單頁 HTML 教材**，之後會被放進學習網站，由網站的 iframe 顯示。網站會記錄孩子的學習時間、每題對錯和未做，**但前提是你的 HTML 在適當時機回報**。請嚴格按以下規則製作。

## 一、基本要求
1. **單一 HTML 檔**：CSS、JS 全部寫在同一個檔內；圖片用 `data:` URI。不要引用外部網路資源（CDN、外部字體、外部圖片），也不要用 `localStorage` 自己存進度（網站會統一記錄）。
2. **不得出現個人資料**：不要寫孩子的真實姓名、暱稱、學校名稱、住址。需要稱呼時用「女兒」或「兒子」。網站是公開的，這點非常重要。班別（如「3D」）可以寫。
3. 繁體中文，字體用系統字體：`"PingFang TC","Microsoft JhengHei",sans-serif`。
4. **適應各種螢幕**：主要場景是 65 寸 4K 觸控投屏機（**先讀第二節，版面按它設計**），其次才是平板、電腦、手機。用 `rem`、`vmin`、`clamp()` 等相對單位；不要依賴滑鼠懸停；不要依賴鍵盤快捷鍵（觸控屏沒有實體鍵盤，每個功能都要有可點的按鈕）。
5. 頁面會放在 iframe 內，上方有一條約 3.6rem 的網站工具列。頁面高度請用 `100%`（不要用 `100vh` 加額外邊距）。
6. 設定有意義的 `<title>`（不含個人資料）。

## 二、最主要的使用場景：65 寸觸控投屏機（版面必須先按這個設計）
規格：螢幕寬約 145 cm、高約 83 cm，16:9 橫向，4K，**觸控**。孩子用手指在螢幕前操作，內容同時投給旁邊的人看。手機和平板只是次要場景，窄屏（寬度小於 900px 或直向）時才改為上下堆疊。

### A. 版面：寬而矮，用「左右分欄」，不要上下堆疊
1. 主版面分**左右兩欄**（約 55:45 或 60:40）：一側放題目和圖形，另一側放選項、作答區、答案說明。題號、進度、指示語、單元名稱**全部放進欄位內**。
2. **不要做橫跨整個寬度的頂部標題列**。若一定要有固定頂部列，總高度不超過視窗高度的 6%（`6vh`），只放題號或進度之類極少的內容；標題和單元名稱放在左欄內，跟著內容走。
3. **不要用 `position: fixed` 的底部操作列**（上一題／下一題／提交）。底部會被螢幕鍵盤蓋住。操作按鈕放在欄位內容流裡，位置在螢幕上半部到中間。
4. **一屏一題**，整頁不要捲動；內容放不下時只在欄位內部捲動。
5. 字體要能在 2 到 3 米外看清（1 vmin ≈ 0.83 cm）：題幹 `3.6vmin` 至 `5vmin`，選項 `3vmin` 至 `4vmin`，說明文字不小於 `2.4vmin`，一律配合 `clamp()` 給手機設下限。
6. 網站會在頁面上方加一條約 3.6rem 的工具列，頁面高度用 `100%`，不要再用 `100vh`。

### B. 需要輸入文字或數字的題目（填充題、問答）
Windows 螢幕鍵盤會從下方彈出，**蓋住約三分之一到一半的螢幕**，而且網頁收不到「鍵盤彈出」的通知（視窗大小不會改變）。所以：
1. **所有輸入框、題目重點、提交按鈕，都必須放在螢幕上半部（距頂部 55% 以內）**，不論鍵盤有沒有彈出。
2. **數字答案首選：頁面內建大按鈕數字鍵盤**。在右欄放 0 至 9、小數點、退格、清除、確定，每個按鈕不小於 `8vmin`；輸入框設 `readonly` 加 `inputmode="none"`，避免彈出系統鍵盤。只有真正需要打字的文字題才用系統鍵盤。
3. 必須用系統鍵盤時：輸入框設正確的 `inputmode`（`numeric`、`decimal` 或 `text`）；聚焦時把輸入框捲到視窗上方；並在頁面最底留 `50vh` 空白，讓位置較低的輸入框也能捲上來：

```css
html{scroll-padding-top:12vh}
input,textarea{scroll-margin-top:12vh}
.scroll-area::after{content:"";display:block;height:50vh} /* 放在會捲動的欄位最底，給鍵盤讓位 */
```
```js
document.addEventListener("focusin",function(e){
  var el=e.target;
  if(el.matches("input,textarea"))setTimeout(function(){el.scrollIntoView({block:"start",behavior:"smooth"});},150);
});
```
4. 有多個空格的填充題：空格排在題目所在欄位的**上半部**，不要排到螢幕下方。
5. 輸入框高度不小於 `8vmin`、字體不小於 `4vmin`。不用小型下拉選單，改用大按鈕選擇。
6. 「確定／提交」按鈕緊貼輸入區，放在上半部。

### C. 觸控操作
1. 主要可點擊區域的高度和寬度用 `min-height:max(3rem,7vmin)`（大屏約 6 cm，手機不小於 3rem）。
2. 不要用拖放作為唯一操作方式。拖放題必須同時支援「先點選項，再點目標位置」。
3. 不依賴雙擊、長按、右鍵、懸停。加上 `touch-action: manipulation`，避免誤觸縮放。
4. 兩個可點擊區域之間留足間距，避免手指誤觸。

## 三、作答回報（有任何要孩子作答的題目就必須加）
把下面兩個函式**原樣**放在 `<script>` 最前面：

```js
// ---- E_learning Hub 回報（只在被網站 iframe 載入時有效，單獨打開頁面時無任何作用）----
function elhReport(m){
  try{
    if(location.search.indexOf("elhdebug")>=0)console.log("ELH",JSON.stringify(m));
    if(window.parent!==window)window.parent.postMessage(Object.assign({elh:1},m),location.origin);
  }catch(e){}
}
function elhText(h){return String(h==null?"":h).replace(/<[^>]*>/g,"").replace(/\s+/g," ").trim().slice(0,200);}
```

### 1) 載入時回報總題數（一次）
```js
elhReport({type:"init", total: 題目總數});
```
`total` 只算**需要孩子作答的題目**數量，必須準確：網站用「總題數 − 已答題數」計算「未做」。

### 2) 每題「揭曉答案／批改」那一刻回報（每題一次）
```js
elhReport({
  type: "answer",
  q: 題號,            // 同一份教材內唯一（數字或字串）
  choice: 孩子的作答,  // 孩子有作答：選項序號、或輸入的文字（任何非 null 的值）；沒作答就看答案：null
  correct: true/false, // 是否答對（沒作答時填 false）
  text: elhText(題目文字),
  picked: 孩子的作答文字或 null,   // 例如所選選項的文字、或填空輸入的內容
  answer: elhText(正確答案文字)
});
```

### 各題型怎麼回報
| 題型 | `choice` | `picked` | `correct` |
|---|---|---|---|
| 選擇題 | 所選選項序號（0 起） | 所選選項文字 | 所選是否等於正確選項 |
| 填充題（多個空格） | 孩子填的內容（如 `"7|65"`） | 同上，用 ` / ` 隔開各空格 | **所有空格都對**才是 true |
| 配對／排序題 | 孩子提交的結果（字串） | 孩子提交的結果文字 | 完全正確才是 true |
| 沒作答就按「顯示答案」 | `null` | `null` | `false` |

### 回報時機的規則
- **只在答案被揭曉或提交批改那一刻回報**，不要在孩子還在選擇時回報。
- 孩子可以改答案再提交時，**每次提交都回報一次**，網站以同一題最後一次為準。
- 若頁面有「先選、再按顯示答案」的流程（像一般投影練習），在「顯示答案」按鈕的處理函式裡回報。
- 回報內容不得包含個人資料。

## 四、沒有作答的教材
純閱讀頁、知識卡片、影片等**沒有題目**的頁面，不需要任何回報，網站仍會記錄開始時間、停留時間和「完成」。

## 五、交付前自我檢查
- [ ] 單一 HTML 檔、無外部資源、無 `localStorage`
- [ ] 全檔搜尋過，沒有孩子姓名、暱稱、學校
- [ ] 所有功能都有可點的按鈕，不靠鍵盤
- [ ] 以 3840×2160 和 1920×1080（16:9 橫向）檢查過：左右分欄，沒有橫跨整寬的頂部標題列，沒有固定在底部的操作列，整頁不捲動
- [ ] 所有輸入框和提交按鈕都在螢幕上半部（距頂部 55% 以內）；數字題有頁面內建大按鈕數字鍵盤
- [ ] 模擬「底部 40% 被鍵盤蓋住」：把視窗高度想成只剩 60%，仍能看到題目、輸入框和提交按鈕
- [ ] 拖放題同時支援「先點選、再點目標」；可點擊區域不小於 `max(3rem,7vmin)`
- [ ] 窄屏（寬度小於 900px）時改為上下堆疊，仍可正常使用
- [ ] 有題目的頁面：已放入 `elhReport` / `elhText`，`init` 的 `total` 等於題目數
- [ ] 每題揭曉答案時都有回報；用瀏覽器開 `你的檔案.html?elhdebug`，開發者工具 Console 作答一輪，確認每題都印出一行 `ELH {...}`，且 `correct`、`choice` 符合預期
- [ ] 沒作答直接看答案的情況：`choice` 為 `null`

完成後把 HTML 檔交給負責上傳的人，並說明：科目、適用階段、教材類型、預計學習分鐘數、題目數。
